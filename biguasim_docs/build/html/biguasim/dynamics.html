class biguasim.dynamics.uav.QuadCopterX(batch_size: int, params: dict, device: str, control_abstraction: str)

Bases: VehicleModel

Concrete vehicle model for a standard X-frame quadrotor operating in air only.

Extends VehicleModel with a full rigid-body dynamics pipeline and a cascaded SE(3) control architecture. Operates in a single domain (air) with a square 4×4 allocation matrix mapping [thrust, Mx, My, Mz] to 4 rotor speeds exactly.

Control abstractions supported:

  • ‘cmd_motor_speeds’ : Direct rotor speed pass-through.

  • ‘cmd_vel’ : 3D velocity tracking using SE(3) attitude control.

  • ‘cmd_vel_yaw’ : 3D velocity + relative yaw offset [vx, vy, vz, yaw_deg].

  • ‘cmd_pos_yaw’ : 3D position + absolute yaw [x, y, z, yaw_deg].

Control architecture (cmd_vel / cmd_vel_yaw / cmd_pos_yaw):

Position PD → Velocity P → Desired force F_des F_des → Desired orientation R_des (SE(3) geometric controller) R_des → Attitude error → Desired moment M_des [T, M_des] → TM_to_f (allocation inverse) → Rotor thrusts → Motor speeds

Frame conventions (inherited from VehicleModel):

  • World frame : Z-up, right-handed.

  • Body frame : X-forward, Y-left, Z-up.

Parameters:

  • batch_size (int) – Number of vehicles simulated in parallel.

  • params (dict) – Vehicle parameter dictionary.

  • device (str) – Torch device string, e.g. ‘cpu’ or ‘cuda:0’.

  • control_abstraction (str) – One of the supported control abstraction keys above.

get_cmd_motor_speeds(state: dict, control: dict) → torch.Tensor

Converts a high-level control command into rotor speed commands using a geometric SE(3) controller cascaded with optional position and yaw loops.

All three non-passthrough abstractions share the same inner loop:

  1. Compute desired force F_des from velocity or position error.

  2. Derive desired orientation R_des that aligns body +Z with F_des and body +X with the desired yaw heading (Gram-Schmidt).

  3. Compute orientation error via the skew-symmetric error matrix:

    S_err = ½ (R_des^T R − R^T R_des) att_err = vee(S_err) (extracts the Lie algebra error vector)

  4. Compute desired moment via PD law on att_err and angular velocity, with gyroscopic feedforward: M = I(−kp e_R − kd ω) + ω × Iω

  5. Map [T, Mx, My, Mz] through TM_to_f to rotor thrusts.

  6. Convert rotor thrusts to signed motor speeds: ω = sign(F)√(|F|/k_eta).

Large-yaw guard (cmd_vel_yaw and cmd_pos_yaw):

When |ψ_des| > π/2, c1_des flips sign and breaks the Gram-Schmidt frame construction. In this case, the rotation matrix R is taken from the quaternion composed with the yaw offset (R_r) rather than the raw state quaternion (R_q), preventing discontinuities near ±π.

Parameters:

  • state (dict) – Structured state dict {x, v, q, w} from VehicleModel.map_states.

  • control (dict) – Control command dict with key ‘cmd_ctrl’ (B, D). D = 3 for cmd_vel, D = 4 for cmd_vel_yaw / cmd_pos_yaw.

Returns:

Rotor speed commands (B, n_rotors), signed rad/s.

Sign encodes spin direction for yaw torque allocation.

Return type:

Tensor

class biguasim.dynamics.uuv.HexaCopterFiveDoF(batch_size: int, params: dict, device: str, control_abstraction: str)

Bases: VehicleModel

Concrete vehicle model for a 5-DOF underwater hexarotor (BlueROV2-style).

Extends VehicleModel with hydrodynamic external forces and a 6×6 wrench allocation for a vehicle that operates exclusively underwater. The frame carries 6 thrusters arranged as follows:

Thrusters 0–1 : vertical (body +Z), control heave and roll. Thrusters 2–5 : horizontal, angled ±45° in the body XY-plane,

control surge (X), sway (Y), and yaw (Mz).

The vehicle is 5-DOF because pitch (My) is structurally unconstrained — the symmetric thruster layout produces no net pitch moment, and no pitch controller is included. self.gen_moments enforces this by zeroing the pitch row of all computed moment vectors.

Physics model:

  • Buoyancy with a linear entry ramp near the surface (dumping_hack).

  • Quadratic translational drag: −½ρ Cp v|v| (isotropic sphere model).

  • Quadratic rotational drag: −½ρ L Cr ω|ω| (isotropic sphere model).

  • Added mass from displaced fluid volume (sphere approximation).

  • Coriolis/centrifugal term: ω × (m v).

  • Gyroscopic moment: −ω × (I ω).

Control abstractions supported:

  • ‘cmd_motor_speeds’ : Direct thruster speed pass-through.

  • ‘cmd_vel’ : 3D velocity tracking [vx, vy, vz].

  • ‘cmd_vel_yaw’ : 3D velocity + yaw offset [vx, vy, vz, yaw_deg].

  • ‘cmd_pos_yaw’ : 3D position + absolute yaw [x, y, z, yaw_deg].

Control architecture (all non-passthrough abstractions):

Velocity/Position P(D) → desired force F_des (body frame) Roll PID → desired roll moment M_roll Yaw PD → desired yaw moment M_yaw [F_des, M_roll, M_yaw] → TM_to_f (pseudo-inverse) → thruster forces Thruster forces → bidirectional motor speeds

Frame conventions (inherited from VehicleModel):

  • World frame : Z-up, right-handed (NWU).

  • Body frame : X-forward, Y-left, Z-up.

Parameters:

  • batch_size (int) – Number of vehicles simulated in parallel.

  • params (dict) – Vehicle parameter dictionary.

  • device (str) – Torch device string, e.g. ‘cpu’ or ‘cuda:0’.

  • control_abstraction (str) – One of the supported control abstraction keys.

Methods:

get_cmd_motor_speeds(state: dict, control: dict) → torch.Tensor

Converts a high-level control command into bidirectional thruster speed commands using a cascaded P(D) velocity/position controller with independent roll PID and yaw PD inner loops.

All three non-passthrough abstractions share the same inner loop:

  1. Compute desired force F_des (body frame) from velocity or position error.

  2. Compute desired roll moment M_roll via PID on roll rate.

  3. Compute desired yaw moment M_yaw via PD on yaw error.

  4. Assemble wrench [F_des, M_roll, 0, M_yaw] and map through TM_to_f.

  5. Convert thruster forces to bidirectional motor speeds: ω = sign(F) √(|F| / k_eta).

The pitch channel is always zero in the wrench vector, consistent with the 5-DOF design and the gen_moments mask applied in _compute_external_forces.

Parameters:

  • state (dict) – Structured state dict {x, v, q, w} from VehicleModel.map_states.

  • control (dict) – Control command dict with key ‘cmd_ctrl’ (B, D). D = 3 for cmd_vel, D = 4 for cmd_vel_yaw / cmd_pos_yaw.

Returns:

Thruster speed commands (B, 6), signed rad/s.

Return type:

class biguasim.dynamics.uuv.OctaCopterSixDoF(batch_size: int, params: dict, device: str, control_abstraction: str)

Bases: HexaCopterFiveDoF

Fully actuated 6-DOF underwater vehicle model with 8 thrusters arranged in two functional groups:

  • 4 vertical thrusters (indices 0–3): produce Z-axis thrust and roll/pitch moments via differential thrust.

  • 4 horizontal thrusters (indices 4–7): oriented at ±45° in the XY body plane, producing surge (X), sway (Y), and yaw (Mz) forces.

Extends HexaCopterFiveDoF by adding full roll and pitch moment authority through the vertical thruster group, upgrading the vehicle from 5-DOF to 6-DOF control.

All thrusters are bidirectional — motor speed commands carry sign (positive = one spin direction, negative = the other), and thrust is proportional to ω|ω| = ω² sign(ω).

Control abstractions supported:

  • ‘cmd_motor_speeds’ : Direct thruster speed pass-through.

  • ‘cmd_vel’3D velocity tracking [vx, vy, vz]

    with heading-hold yaw stabilization.

  • ‘cmd_vel_yaw’3D velocity + relative yaw offset

    [vx, vy, vz, yaw_deg].

  • ‘cmd_pos_yaw’3D position + absolute yaw

    [x, y, z, yaw_deg].

Control architecture:

(optional) Position P → Velocity P → Desired force F_des F_des → Wrench [F, M] → TM_to_f (allocation)

→ Thruster forces → Motor speeds

Attitude stabilization:

Roll and pitch are stabilized by independent PID controllers acting on angular rate (w[:, 0] and w[:, 1] respectively). Yaw is controlled by a PD law on the yaw angle error and yaw rate.

Frame conventions (inherited from VehicleModel):

  • World frame : Z-up, right-handed.

  • Body frame : X-forward, Y-left, Z-up.

Parameters:

  • batch_size (int) – Number of vehicles simulated in parallel.

  • params (dict) – Vehicle parameter dictionary.

  • device (str) – Torch device string, e.g. ‘cpu’ or ‘cuda:0’.

  • control_abstraction (str) – One of the supported control abstraction keys above.

get_cmd_motor_speeds(state: dict, control: dict) → torch.Tensor

Converts a high-level control command into thruster speed commands using a cascaded P-control architecture with independent attitude stabilization.

All three non-passthrough abstractions share the same inner structure:

  1. Compute desired force F_des from velocity or position error.

  2. Stabilize roll and pitch via PID on angular rates w[:, 0], w[:, 1].

  3. Control yaw via PD on yaw angle error and yaw rate.

  4. Assemble wrench [F_des, M_des] and map through TM_to_f.

class biguasim.dynamics.uuv.TorpedoAUV(batch_size: int, params: dict, device: str, control_abstraction: str)

Bases: VehicleModel

6-DOF torpedo-shaped Autonomous Underwater Vehicle (AUV) model.

Models a slender, neutrally buoyant underwater vehicle propelled by a single stern propeller and steered by two pairs of control surfaces:

  • Rudders (δ_rt, δ_rb): port/starboard tail fins — yaw control.

  • Sternplanes (δ_sl, δ_sr): top/bottom tail fins — depth/pitch control.

All actuators are modeled with first-order lag dynamics (time constants T_delta for fins, T_n for the propeller), so commanded values are not applied instantaneously.

Hydrodynamics:

  • Rigid-body and added-mass Coriolis/centripetal matrices via m2c.

  • Linear damping diagonal, with exponential velocity attenuation on surge and sway at low speeds.

  • Body lift/drag from the hull (flat-plate approximation).

  • Cross-flow drag via strip theory (BatchedParams.cross_flow_drag).

  • Gravitational and buoyancy restoring forces/moments (_gvect).

  • Propeller thrust and torque via an open-water diagram approximation (forward and reverse operating modes handled separately).

Ocean current:

A uniform horizontal current (V_c, β_c) is subtracted from the vehicle velocity to produce the relative velocity ν_r used in all hydrodynamic force computations.

Frame conventions:

  • Internal dynamics use the NED (North-East-Down) body frame.

  • State input/output from VehicleModel uses NWU (North-West-Up).

  • Conversion between frames is handled by tfrm.convert_NWU_to_NED and tfrm.convert_NED_to_NWU at the entry and exit of each step.

Control abstractions supported:
  • ‘cmd_rudders_sterns_motor_speed’:

    Direct pass-through — [δ_rt, δ_rb, δ_sl, δ_sr, n] (rad, rad/s).

  • ‘cmd_depth_heading_rpm_surge’:

    High-level autopilot — [z_ref, ψ_ref_deg, n_rpm, u_ref]. Depth is controlled by a successive-loop PI (z → θ_d → δ_s). Heading is controlled by an integral sliding-mode controller (SMC) with a 3rd-order reference model (z → ψ_d → δ_r). Surge speed is controlled by a PID on forward velocity, or a direct RPM command when surge control is disabled.

Parameters:

  • batch_size (int) – Number of vehicles simulated in parallel.

  • params (dict) – Vehicle parameter dictionary.

  • device (str) – Torch device string, e.g. ‘cpu’ or ‘cuda:0’.

  • control_abstraction (str) – One of the supported control abstraction keys above.

get_cmd_motor_speeds(state: dict, control: dict) → torch.Tensor

Converts a high-level control command into actuator commands [δ_rt, δ_rb, δ_sl, δ_sr, n] using the AUV’s autopilot hierarchy.

Entry point responsibilities:

  1. Convert NWU state to NED pose η and velocity ν for all autopilot computations (tfrm.convert_NWU_to_NED).

  2. Lazily initialize u_actual to zeros on first call.

  3. Dispatch to the appropriate control abstraction.

Control abstractions:

‘cmd_rudders_sterns_motor_speed’:

Pass-through — returns raw [δ_rt, δ_rb, δ_sl, δ_sr, n] commands directly from control[‘cmd_ctrl’], bypassing all autopilot logic.

‘cmd_depth_heading_rpm_surge’:

Simultaneous depth, heading, and speed autopilot. Input: [z_ref (m), ψ_ref (deg), n_rpm, u_ref (m/s)]

If both n_rpm and u_ref are zero, returns zero commands (vehicle stopped).

Surge control (when u_ref > 0):

PID on forward velocity error (u − u_ref). n = Kp_surge * e + Ki_surge * ∫e + Kd_surge * ė Integrated and clamped to ±nMax RPM.

Surge open-loop (when u_ref = 0):

n = n_rpm directly.

Depth autopilot (successive loop closure):

Step 1: LP filter z_ref → z_d with bandwidth wn_d_z. Step 2: PI on depth error → desired pitch θ_d:

θ_d = Kp_z * [(z − z_d) + (1/T_z) * ∫(z − z_d)] Saturated to ±theta_max.

Step 3: PID on pitch error → sternplane deflection δ_s:

δ_s = −Kp_θ ssa(θ−θ_d) − Kd_θ q − Ki_θ ∫(θ−θ_d) − K_w w

Heading autopilot (integral SMC):

Integral SMC with 3rd-order reference model (see integralSMC). Drives ψ → ψ_ref via rudder deflection δ_r. Reference model state (ψ_d, ṙ_d, r̈_d) persists between steps.

Final command assembly:

δ_rt = δ_rb = δ_r (symmetric rudder pair) δ_sl = δ_sr = δ_s (symmetric sternplane pair) Output: [δ_rt, δ_rb, δ_sl, δ_sr, n]

Parameters:

  • state (dict) – Structured state dict {x, v, q, w} from VehicleModel.map_states.

  • control (dict) – Control command dict with key ‘cmd_ctrl’ (B, D).

Returns:

Actuator commands (B, 5): [δ_rt, δ_rb, δ_sl, δ_sr, n].

Return type:

Tensor

static integralSMC(e_int: torch.Tensor, e_x: torch.Tensor, e_v: torch.Tensor, x_d, v_d, a_d, T_nomoto: torch.Tensor, K_nomoto: torch.Tensor, wn_d: torch.Tensor, zeta_d: torch.Tensor, K_d: torch.Tensor, K_sigma: torch.Tensor, lam: torch.Tensor, phi_b: torch.Tensor, r, v_max: torch.Tensor, sampleTime: float)

Integral Sliding Mode Controller (ISMC) with a 3rd-order reference model.

Designed for heading (yaw) autopilot of a vessel whose yaw dynamics are approximated by Nomoto’s first-order model:

T_nomoto * ṙ + r = K_nomoto * δ

The controller drives the yaw angle error e_x = ψ − ψ_d to zero while using an integral term e_int to eliminate steady-state offset.

Sliding surface:

σ = ė_x + 2λ e_x + λ² e_int

Control law (smooth inside boundary layer, sign outside):

δ = [T_nomoto * v̇_r + v_r − K_d σ − K_σ sat(σ/φ_b)] / K_nomoto

where v_r = v_d − 2λ e_x − λ² e_int (reference velocity)

v̇_r = a_d − 2λ ė_x − λ² e_x (reference acceleration) sat(·) = σ/φ_b if |σ/φ_b| ≤ 1, sign(σ) otherwise

Reference model (3rd-order, inner function refModel3):

Generates smooth desired trajectories (x_d, v_d, a_d) from a step reference r, with natural frequency wn_d and damping zeta_d. Desired velocity is clamped to ±v_max for safety.

Parameters:

  • e_int – Integral of yaw error (B,).

  • e_x – Yaw angle error ψ − ψ_d (B,).

  • e_v – Yaw rate error r − r_d (B,).

  • x_d – Current desired yaw angle from reference model.

  • v_d – Current desired yaw rate from reference model.

  • a_d – Current desired yaw acceleration from reference model.

  • T_nomoto – Nomoto time constant (B,).

  • K_nomoto – Nomoto gain (B,).

  • wn_d – Reference model natural frequency (rad/s).

  • zeta_d – Reference model damping ratio.

  • K_d – SMC damping gain on σ.

  • K_sigma – SMC switching/smoothing gain on sat(σ/φ_b).

  • lam – Sliding surface pole location λ > 0.

  • phi_b – Boundary layer thickness φ_b > 0.

  • r – Step reference (desired heading) (B,).

  • v_max – Maximum allowed desired yaw rate (rad/s).

  • sampleTime – Integration timestep (s).

Returns:

delta : Rudder deflection command (B,) in radians. e_int : Updated integral error state. x_d : Updated desired position from reference model. v_d : Updated desired velocity from reference model. a_d : Updated desired acceleration from reference model.

Return type:

tuple

class biguasim.dynamics.usv.Catamaran(batch_size: int, params: dict, device: str, control_abstraction: str)

Bases: VehicleModel

Surface vessel model for a catamaran hull with 2 differential thrusters.

Models a twin-hull surface vessel that operates at the water surface. Propulsion is provided by two bidirectional thrusters mounted along the surge axis; differential thrust between them produces yaw moments, making this a 2-DOF actuated vehicle (surge + yaw).

The vehicle is constrained to the water surface — sway, heave, roll, and pitch are not actively controlled, though their dynamics are modeled via hydrodynamic drag and buoyancy restoring forces.

Thruster layout (body frame):

Thruster 0 (r1): port — positive speed = forward thrust Thruster 1 (r2): starboard — positive speed = forward thrust Differential (T0 − T1) → yaw moment Mz

Buoyancy model:

A sigmoid-ramp damping factor scales the buoyancy force from zero (above the waterline) to a maximum proportional to hull submersion depth. The dumping_hack multiplier is reduced to 0.5 when both thrusters are active, reflecting the reduced effective buoyancy under dynamic operation.

Drag model:

Quadratic translational drag: D = −½ρ Cp v|v| Quadratic rotational drag: M = −½ρ L Cr ω|ω| Coefficients based on Hoerner (1965), pg. 60, Cd = 0.38.

Frame conventions (inherited from VehicleModel):

  • World frame : Z-up, right-handed.

  • Body frame : X-forward, Y-left, Z-up.

Control abstractions supported:

  • ‘cmd_motor_speeds’ : Direct thruster speed pass-through.

  • ‘cmd_vel’Surge velocity tracking [vx, vy, vz]

    (only vx is controlled; vy, vz are zeroed).

  • ‘cmd_vel_yaw’ : Surge velocity + relative yaw offset [vx, _, _, yaw_deg].

  • ‘cmd_pos_yaw’2D position tracking; yaw is steered toward

    the bearing to the goal [x, y, z, _].

Parameters:

  • batch_size (int) – Number of vehicles simulated in parallel.

  • params (dict) – Vehicle parameter dictionary.

  • device (str) – Torch device string, e.g. ‘cpu’ or ‘cuda:0’.

  • control_abstraction (str) – One of the supported control abstraction keys above.

get_cmd_motor_speeds(state: dict, control: dict) → torch.Tensor

Converts a high-level control command into thruster speed commands using a cascaded P-control architecture for surge and yaw.

All three non-passthrough abstractions share the same inner structure:

  1. Compute desired surge force F_des from a velocity error (optionally preceded by a position → velocity outer loop).

  2. Compute desired yaw moment M_yaw from a yaw angle PD law.

  3. Assemble wrench [F_des, M_des] and map through TM_to_f.

  4. Convert thruster forces to signed motor speeds: ω = sign(F) * √(|F| / k_eta).

Surge-only constraint:

This vehicle can only actuate surge (X) and yaw (Mz). Sway, heave, roll and pitch commands are zeroed before force computation to prevent spurious allocation outputs.

cmd_pos_yaw bearing computation:

The desired yaw is not taken from the goal vector but is computed as the geometric bearing to the goal position: ψ_des = atan2(y_goal − y, x_goal − x). This steers the vehicle toward the target rather than commanding an absolute world heading.

Parameters:

  • control (dict) – Control command dict with key ‘cmd_ctrl’ (B, D). D = 3 for cmd_vel, D = 4 for cmd_vel_yaw / cmd_pos_yaw.
